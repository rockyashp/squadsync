1.   Introduction  
1.1   Purpose   The   purpose   of   this   Software   Requirements   Specification   (SRS)   is   to   define   the   functional   and   non-functional   requirements   of   SquadSync,   an   AI-powered   web   application   designed   to   help   multiplayer   gamers   find   compatible   teammates   based   on   gaming   behavior,   communication   style,   preferred   roles,   and   gaming   schedules.   The   platform   aims   to   improve   team   coordination,   reduce   mismatched   squads,   and   enhance   the   overall   gaming   experience   through   intelligent   matchmaking,   gamer   profiling,   and   real-time   communication.   This   document   serves   as   a   reference   for   developers,   testers,   project   supervisors,   and   stakeholders   throughout   the   software   development   lifecycle.

1.4   Product   Scope   SquadSync   is   an   AI-powered   web   platform   developed   to   simplify   team   formation   in   multiplayer   games   by   recommending   compatible   teammates   based   on   behavioral   analysis   instead   of   relying   solely   on   gaming   rank.   The   system   introduces   the   concept   of   Gamer   DNA,   which   analyzes   a   player's   gaming   personality,   preferred   role,   communication   style,   teamwork,   and   play   schedule   through   a   structured   survey.   Using   Machine   Learning   algorithms,   SquadSync   recommends   suitable   teammates,   predicts   player   roles,   and   assists   in   forming   balanced   gaming   squads.   In   addition   to   intelligent   matchmaking,   the   platform   provides   gamer   profile   management,   friend   management,   real-time   messaging,   team   dashboards,   and   gaming   news,   creating   a   centralized   platform   for   multiplayer   gaming   communities.   The   system   demonstrates   the   integration   of   Software   Engineering,   Web   Development,   Recommendation   Systems,   and   Machine   Learning   to   solve   real-world   challenges   in   online   gaming.

2.3   User   Classes   and   Characteristics   The   system   primarily   supports   two   categories   of   users   based   on   their   access   privileges   and   responsibilities.  
1.   Gamers   (Primary   Users)   Gamers   are   the   primary   users   of   the   platform.   They   can   register,   create   and   manage   their   gaming   profiles,   complete   the   Gamer   Survey,   receive   AI-powered   teammate   recommendations,   send   and   accept   friend   requests,   create   or   join   teams,   communicate   through   one-to-one   and   team   chat,   and   view   gaming   news   and   updates.   A   gamer   who   creates   a   team   is   automatically   assigned   as   the   team   owner   and   is   provided   with   additional   team   management   options   such   as   inviting   or   removing   members   and   managing   basic   team   settings.   These   are   additional   permissions   rather   than   a   separate   user   role.   Users   are   expected   to   have   basic   computer   skills   and   familiarity   with   online   multiplayer   games.  
2.   Administrator   Administrators   are   responsible   for   managing   the   overall   platform.   They   can   manage   user   accounts,   review   reported   users   or   content,   moderate   inappropriate   activities,   monitor   system   usage,   and   maintain   the   security   and   integrity   of   the   application.   Administrators   have   full   access   privileges   that   are   not   available   to   regular   users.

5.2   Safety   Requirements   NF-2.1:   Since   automated   backups   are   not   guaranteed   by   the   host,   manual   or   scripted   data   preservation   for   profiles   and   chat   history   must   be   conducted   at   key   milestones.   NF-2.2:   Proactive   measures   will   be   taken   to   ensure   the   backend   and   database   remain   active   during   scheduled   evaluations   to   prevent   suspension   due   to   idle   states.   NF-2.3:   If   the   AI   engine   or   third-party   APIs   fail,   the   system   must   degrade   gracefully,   maintaining   the   availability   of   core   features   like   profile   management   and   chat.   NF-2.4:   To   manage   security   without   paid   resources,   a   cooling-off   period   will   be   triggered   after   multiple   unsuccessful   login   attempts   to   deter   unauthorized   access.  
5.3   Security   Requirements   NF-3.1:   Accessing   secure   system   resources   requires   a   valid   JWT,   which   is   generated   only   upon   a   verified   user   login.   NF-3.2:   Plaintext   password   storage   is   prohibited;   all   credentials   must   be   secured   using   industry-standard   hashing   techniques   like   bcrypt   before   being   saved.   NF-3.3:   All   traffic   between   the   client   and   server   must   be   encrypted   via   HTTPS   to   protect   data   while   it   is   in   transit.   NF-3.4:   Role-based   permissions   will   be   enforced   to   distinguish   between   standard   users   and   administrators,   limiting   sensitive   functions   to   authorized   personnel.   NF-3.5:   API   endpoints   must   validate   and   sanitize   all   user   input   to   mitigate   risks   associated   with   SQL   injection   and   cross-site   scripting   (XSS).

5.4   Software   Quality   Attributes   Reliability:   The   application   is   designed   to   be   stable   during   evaluation   phases,   with   performance   expectations   aligned   with   its   academic   purpose   rather   than   production-grade   SLAs.   Usability:   The   interface   will   utilize   a   coherent   design   language,   allowing   new   users   to   navigate   the   survey   and   teammate   recommendations   intuitively.   Maintainability:   Code   will   be   structured   into   modular   blocks   for   matchmaking   and   chat,   facilitating   updates   without   disrupting   independent   sections   of   the   platform.   Portability:   The   frontend   will   support   responsive   viewing   across   browsers,   while   the   backend   will   maintain   consistency   across   various   hosting   environments.   Explainability:   Teammate   recommendations   will   include   human-readable   justifications,   such   as   shared   gaming   roles   or   schedules,   providing   context   beyond   simple   scores.   Cost   Constraint:   The   entire   application   must   be   maintainable   at   no   financial   cost,   adhering   to   its   scope   as   a   non-commercial   student   deliverable.  
5.5   Business   Rules   BR-1:   Users   are   required   to   finalize   the   Gamer   Survey   to   become   eligible   for   any   AI-powered   matchmaking   services.   BR-2:   Networking   and   friend   requests   are   restricted   between   accounts   where   a   block   or   report   has   been   previously   initiated.   BR-3:   Access   to   team-specific   dashboards   is   strictly   limited   to   the   current   members   of   that   particular   squad.   BR-4:   Administrative   access   will   be   granted   manually   by   the   developers   rather   than   via   public   registration,   fitting   the   academic   context   of   the   project.   BR-5:   Teammate   suggestions   will   be   updated   dynamically   following   changes   to   a   user's   profile   or   survey   data   rather   than   on   a   fixed   cycle.   BR-6:   Flagged   content   or   reported   profiles   will   undergo   administrator   review   within   a   48-hour   window   before   any   moderation   actions   are   applied.
